# タイムカードOCR

画像の表指定、行列編集、OCR、結果修正、CSV・SQLite書出しをブラウザー内で行うツールです。一括・選択セルの再OCRとも、同じPP-OCRv5を使います。画像やOCR結果を外部サーバーへ送信しません。

## 開発環境で起動する

Python 3とNode.jsを用意し、リポジトリのルートで実行します。Pythonは開発用の静的ファイル取得・配信に使い、OCR自体はブラウザー内のWebAssemblyで実行します。

```powershell
python scripts/prepare-timecard-browser.py --download
python -m http.server 9097 --bind 127.0.0.1 --directory www
```

ブラウザーで http://127.0.0.1:9097/test/timecard-ocr/ を開きます。初回は「準備する」から認識データをブラウザーへ保存してください。既存データを保存済みなら準備欄は表示されません。コードの更新確認は `/test/timecard-ocr/update.html` から行えます。

モデル・実行ライブラリはGitに含めず、固定URLとSHA-256を記録した台帳から取得します。取得には通信が必要です。取得後の画像処理・認識は端末内で実行します。

## 操作

1. 画像を選ぶか、元画像欄へドロップします。
2. ①カード補正で「用紙定義」からテンプレートや定義JSONを選びます。「カードの四隅を自動検出」または手動調整でカード全体の外周を合わせ、「カード補正を確定」で②へ進みます。
3. ②読取範囲で「表／カード情報」を切り替え、補正済みカード上に表の抽出範囲とNo.・氏名・所属・年月の枠を指定します。表は「表の四隅を自動指定」でも仮配置できます。「読取範囲を確定」で③へ進みます。カード情報の未定義項目があっても表の作業は続けられます。
4. ③行列調整で行列・見出し・本文の回転を調整します。「行列を自動配置」は行数・列数を維持し、選んだ対象範囲の行／列／両方だけに適用します。列見出しは本文の回転から除外します。「調整完了」で④へ進みます。
5. ④OCR・確認で「一括OCRを実行」、またはセルを選んで「選択セルを再OCR」を実行します。一括は100×100px以上の余白を含む原色の結合画像全体を1回でOCRし、文字の位置から各セルへ戻します。対応ブラウザーでは最大4スレッドで計算します。
6. 原画像と結果を照合し、結果表の右隣の確認欄で必要な値を修正して保存します。結果表と確認欄の境界もドラッグで幅を変えられます。勤務表CSV・カード情報CSV・証跡CSV・SQLiteは④の「結果を書き出す」から選びます。

初期の用紙定義は「アマノタイムカード」です。指定された定義の17行・9列、カード情報4枠、表の範囲、回転と列別色除去を使用します。作業JSONを開く場合はその作業の用紙定義を優先します。アマノの既定見出し列は左端の日付です。旧既定で9列目が指定されている場合は初回の読込時だけ日付列へ移行し、その後の手動指定は保持します。画像を新しく開いたとき、①の4点は画像全体の四隅に配置します。サンプルや、点が空の旧作業にも適用します。保存済みの途中点・確定点は保持します。

現在の工程に対応する「①の詳細設定」から「④の詳細設定」だけを表示します。①と②の表指定では、各点のX・Yを数値欄のアップダウンで調整できます。用紙定義の読込・テンプレート選択・JSON編集は①へまとめ、②③の詳細設定からも最新の用紙定義を保存できます。「作業保存・再開」は①の途中から利用でき、現在工程と途中の設定も保存します。到達済みの工程への移動や設定の開閉だけではOCR結果を破棄しません。

①～③の常設「戻す／やり直す」、Ctrl+Z／Ctrl+Y（またはCtrl+Shift+Z）で、その工程内の選択・点・枠・行列定義を戻せます。文字入力中は文字編集の標準ショートカットを優先します。工程移動・画像入替で編集履歴を区切り、OCRの認識履歴とは分けます。見出し名のポップアップは「列名／行名」を切り替えてそれぞれ編集し、列名はcolumns[].label、行名はrow_labelsとして独立して保存します。未命名の列は見出し指定の有無によらず「列9」のように表示します。

③の編集画像の右上に「色を除去」があります。プレビューするセルを選び、除去する部分を囲んでスポイトで色を拾います。色相・彩度・明るさの分布と数値範囲を調整し、必要なら背景色も画像から拾えます。決定すると、囲った範囲と色条件を同じ列の各セルへ同じ割合で適用し、右の切出し画像を直ちに更新します。変更した列のOCR結果は未処理へ戻り、以前の修正履歴は残します。元画像自体は変更しません。③の切出し一覧にはOCRの確認状態を表示しません。

色除去の操作は「除去色を拾う／除去範囲を囲う／背景色を拾う」の1つを選択します。各操作の隣に色見本や座標を並べ、原画像とプレビューの橙枠が適用範囲を表します。その下の色相・彩度・明るさの分布グラフはドラッグで起終点を選べます。逆方向のドラッグも可能です。拾った除去色と、置換する背景色は別々に保持します。

②のカード情報は補正済みカード全体を基準とする割合座標と回転角度で用紙定義へ保存します。旧共通枠のtitle・card_idは廃止し、No.・氏名・所属・年月へ統一しています。旧用紙定義・旧作業を開くときも、この2枠とその重複結果を除外します。現在の4項目や表の結果は保持し、元の作業ファイルは上書きしません。④の結合画像では定義済み項目だけをNo.・氏名・所属・年月の順で上部へ、その下へ表の見出しと本文を行列の関係を保って配置します。結果はカード情報として表示し、選択セルと同じ確認欄で修正できます。カード情報CSVとSQLiteのメタデータにも保存できます。未指定の項目は「範囲未定義」と表示し、座標を推定しません。

④の詳細設定で原色・青除去の比較をONにすると、「青除去後の結合画像」も表示できます。列別色除去は両方の結合画像へ反映され、青除去後には比較用の青除去をさらに適用します。比較OFF時は結合画像だけを使い、表示の切替だけではOCRを実行しません。

「要確認のみ」と理由の絞込は、結果表・カード情報と左の切出し一覧へ同じ条件で適用します。要確認は値のある認識済みセルの低信頼度・形式異常・比較相違です。空欄・空白だけの認識結果、未処理、文字列の種類、年月の未確定だけでは要確認に含めません。空欄の認識が正しいとは限らないため、原画像との照合は必要です。

通常は「絞り込んだ○件を一括承認」で、表示条件に合う未承認の要確認セルを承認します。「一部を選んで承認」では対象選択用のチェックボックスを表示し、結果を閲覧する操作と承認対象の選択を分けます。絞込を変えると選択を解除し、空欄・未処理・条件外のセルは承認しません。確認欄に未保存の編集があるときは、保存または取消をしてから承認します。直後の「取り消す」でその一括承認を戻せます。値やOCR入力を変えたセルの承認は解除します。

アマノタイムカードの列2はX1=9.4%、日付の列名は出勤日・退勤日です。

並列計算にはブラウザーの分離環境を使います。同梱のService Workerが次回の文書読込から必要なヘッダーを付加します。Apacheでは同梱の.htaccessも設定します。分離環境が利用できない場合は1スレッドで動作します。

表示した結合画像そのものをOCR入力へ渡します。画像全体の文字検出1回と、検出した全ての文字行の認識1回で構成するPP-OCRv5の全体パイプラインです。セル別のOCRや失敗時の小分け処理へは切り替えません。原色・青除去の比較ON時だけ画像全体を各1回、計2回処理します。端末のメモリ上限を超えた場合はエラーを表示します。

## モデル・実行方式・使用要件

④のツールバーで「軽量」「標準」「高精度」と「自動」「CPU」「GPU」を選べます。高精度は従来と同じ重みで、新規作業の初期モデルです。軽量はmobile検出・認識、標準はserver検出とmobile認識、高精度はserver検出・認識を使います。速度と精度は画像によって変わります。モデルの説明は選択欄のツールチップで確認できます。

CPU用の認識データは軽量約46MB、標準約129MB、高精度約197MB、GPU用はそれぞれ約61MB、144MB、212MBです。アプリのキャッシュや複数モデルの保存分は別に必要です。切替時に不足する構成だけ「準備する」から保存できます。GPUはWebGPU対応環境で選べ、実際に使用した検出・認識の実行先を表示します。GPU指定の初期化が失敗する場合はCPUを選べます。自動でCPUへ移行した場合も実際の実行先を表示します。

モデル切替だけでは画像と結果は変わりません。作業JSONには選択を保存し、旧作業は高精度・CPUで開きます。「その他」→「使用要件・注意事項」に使用環境、サーバーへの画像・結果の非送信／非保存、端末への手動保存、モデルのキャッシュ、免責を記載しています。

## 型変換と画像の対応確認

④⑤では「カード全体」「切出し」「結合画像」を切り替えられます。画像または結果セルを押すと対応箇所を選択し、拡大・修正画面を右へ表示します。選択枠はOCR画像に焼き込みません。3ペインの境界はドラッグまたは左右キーで調整し、①～③、④、⑤で別々に幅を記憶します。④⑤の初期幅はFHDでおおよそ27:58:15です。

④の「型変換へ進む」または⑤タブで、採用値を列ごとの型へ変換します。型と変換不能時の扱いはツールバーで選び、文字置換・3～4桁の時刻解釈は「⑤の補正設定」で調整します。日付／出勤日／退勤日は日、出勤／退勤は時刻、外出／戻りは時刻またはメモ、残業／小計は時間数が初期値です。No.は識別番号、氏名／所属は文字列、年月は年月です。時刻の型付き値と時間数は分単位です。日だけから年月日を推測せず、空欄は0にしません。

⑤では変換できない値だけを黄色にします。「無視」は元文字列とエラーを残し、黄色表示から外します。修正・照合・一括承認・取消は④から独立し、OCR原文と④の採用値を保持します。承認しても型変換失敗を成功には変えず、型付き値はnullのまま記録します。再OCRや④の採用値・列の型設定を変えると、⑤へ進む際に古い変換修正と承認を解除して再計算します。

作業JSONは⑤の設定・変換結果・修正履歴も保存します。試験や続きの作業では「保存した作業を開く」でOCR済み結果から再開でき、OCRのやり直しは不要です。⑤の勤務表CSVは変換値、証跡CSVは変換前後、SQLiteはOCR結果と変換結果の両方を保存します。①の用紙定義保存にも型設定を含められます。

モデル選択・GPU追加後は168件の自動試験と、合成16セルの各CPU／GPU構成の実認識を確認しています。[モデル選択・GPUの報告](../dev/history/v1.1.0/timecard-models-imp.md)に測定範囲と未検証の条件を記録しています。

実タイムカード、OCR結果、画像由来の作業・校正JSON、CSV、DB、検証画像・動画はこのリポジトリへ含めません。作業保存JSONには画像が入るため、Gitへ追加しないでください。

依存の出典・ライセンスは [THIRD_PARTY.md](../www/test/timecard-ocr/THIRD_PARTY.md) と固定取得台帳に記録しています。このリポジトリは親サイト全体の履歴を含まない、ツール専用のソースです。
